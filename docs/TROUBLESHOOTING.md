# 排查图标未生效

先在框架日志中搜索 `CircleIcons`。每个目标进程会分别记录功能状态：

- `active (数量)`：找到了入口并安装 Hook；是否显示正确仍需检查对应页面。
- `unavailable on this ROM`：该系统没有相应接口。旧 Android 没有新版通知缓存或启动画面入口，属于正常情况。
- `installation failed`：接口结构或框架能力不匹配，日志会带原因，其它功能继续安装。

如果完全没有加载记录，检查模块是否启用、目标 App 是否勾选，以及目标进程是否已在安装后重启。Pixel Launcher 与 Launcher3 是不同包名；系统应用的 Google 版本也有单独的推荐范围。

## 桌面图标没变化

确认系统使用圆形自适应图标蒙版。重启桌面进程或重启手机，再看新启动的桌面。不要清除桌面数据。模块只调整旧式 App 图标，原本的自适应图标会原样交还系统；它们自身绘制在前景里的方形底板不属于自动拆图范围。

桌面版本如果移除或混淆了图标库，系统列表可能已经生效，而桌面缓存仍不变化。请报告桌面包名和版本，以及 `launcher artwork` / `launcher cache version` 两行日志。

## 状态栏仍是方块

确认已启用系统界面范围，并检查 `status bar glyphs` 日志。正确的透明单色图标会直接保留；动画、等级图标和会话头像也不会强制转成静态图片。纯色方块或几乎没有亮度差的素材没有可提取的图案，无法凭空还原品牌标志。

请分别查看当前壁纸、浅色页面与深色页面。模块不写死状态栏颜色，最终着色由 ROM 的 SystemUI 决定；若时钟和系统图标也看不清，应同时排查 ROM 的明暗状态栏设置。

## 回退与停用

在框架管理器中停用模块，然后重启目标进程或手机。模块不更改系统分区，不清除 App 数据，也不重排桌面。升级只安装相同签名的 APK；自己签名的构建无法直接覆盖官方签名版本。

## 提交问题

请使用仓库的兼容性问题模板，提供 Android / ROM 版本、桌面及框架版本、发生位置和最小复现步骤。附 `CircleIcons` 相关日志即可，删除通知正文、账户、设备序列号和网络地址。不要提交完整的系统日志或签名私钥。
